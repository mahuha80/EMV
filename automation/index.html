Concept

Vì sao cần kiến trúc này?

Tách bạch ba lớp: tool/MCP (làm 1 việc cụ thể), decision engine (rule-based, đọc RULES.md), orchestrator (gọi tool theo plan).

🧱

Modular MCP

Mỗi MCP server làm một việc qua JSON-RPC over stdio. Plug thêm/bớt server không cần đổi orchestrator.

📜

Rule-driven

Logic chọn server, chọn bước tiếp theo nằm trong RULES.md — AI đọc và tự quyết định, không hard-code.

🔁

Idempotent & Loggable

Mỗi bước log đầy đủ input/output → có thể replay từng step để debug hoặc audit.

🎫

Jira-first

Input là 1 ticket ID. Output là report + test cases được sinh và đẩy ngược lại Jira/GitHub.

🧪

Test-as-Data

Test cases sinh ra là JSON/YAML có thể chạy bằng Robot Framework hoặc Pytest — không phải prose.

🌐

Stateless services

MCP server không giữ state — dễ scale, dễ deploy độc lập, dễ test unit.

Pipeline

8 bước từ ticket → test cases

Mỗi bước là 1 tool/function độc lập, được orchestrator gọi tuần tự dựa trên rule.

0
step_0_routing

Ticket Number Routing

Tách last digit từ PROJ-1234 bằng regex -(\d+)$ → modulo 10 → chia 2 nhánh EVEN / ODD.

📥 Input: ticket_id 📤 Output: mcp_server_name
1
step_1_mcp_call

Gọi MCP server (JSON-RPC over stdio)

Spawn process MCP, gửi request {"method":"get_random_even", ...}, parse response. Số random làm seed cho test data ở bước sau.

⚙️ random-even-mcp / random-odd-mcp ⏱ < 200ms
2
step_2_fetch_ticket

Fetch ticket từ Jira REST API

Gọi GET /rest/api/3/issue/{id}, parse Atlassian Document Format (ADF) thành plain text cho LLM ăn được.

🔑 Auth: API token 📄 ADF → markdown
3
step_3_extract

Extract: preconditions / steps / expected results

Heuristic parser + LLM fallback. Bóc ra 3 mảng có cấu trúc, validate schema.

📦 Output: TicketModel (Pydantic)
4
step_4_analyze

AI Analyzer — gom domain context

Đọc AI_DECISION_FLOW_RULES.md, ghép với ticket model để chọn template test case phù hợp (smoke / regression / edge).

5
step_5_generate

Generate test cases

LLM sinh test cases theo template, có MCP value làm dynamic input (số tài khoản, giá trị, etc.).

📂 reports/<TICKET>/test_cases.json
6
step_6_validate

Validate & lint

Schema check, duplicate detection, coverage matrix. Fail-fast nếu thiếu acceptance criteria.

7
step_7_deliver

Push lên Jira/GitHub

Comment back Jira ticket với link report, hoặc open PR trên repo test với Robot/Pytest sinh kèm.

🔁 Idempotent — chạy lại không tạo trùng
Routing logic

Even / Odd dispatcher

Quy tắc đơn giản, kiểm chứng được, viết trong RULES.md mục Section 9.

PYTHON# src/ticket_router.py import re def determine_mcp_server(ticket_id: str) -> str: """ R9.1 — Extract last numeric digit from ticket id. R9.2 — even (0,2,4,6,8) → random-even-mcp R9.3 — odd (1,3,5,7,9) → random-odd-mcp """ m = re.search(r"-(\d+)$", ticket_id) if not m: raise ValueError(f"Invalid ticket id: {ticket_id}") last_digit = int(m.group(1)) % 10 return "random-even-mcp" if last_digit % 2 == 0 else "random-odd-mcp"

MCP Protocol

Mỗi tool nói chuyện qua JSON-RPC 2.0

Stdio in/out — tương thích với Claude Desktop, IDE, hoặc bất kỳ host nào hỗ trợ Model Context Protocol.

📤 Request

JSON-RPC{ "jsonrpc": "2.0", "method": "get_random_even", "params": {}, "id": 1 }

📥 Response

JSON-RPC{ "jsonrpc": "2.0", "result": { "number": 18 }, "id": 1 }
SHELL# Chạy thủ công kiểm tra MCP server $ echo '{"jsonrpc":"2.0","method":"get_random_even","params":{},"id":1}' \\ | python3 -m random_even_mcp # Server xử lý từ stdin, trả về stdout — không cần network, không cần port.
